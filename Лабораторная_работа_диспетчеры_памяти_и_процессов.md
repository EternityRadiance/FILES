## 1. Общие правила выполнения лабораторной работы

В окне программной модели отображается событие. Необходимо выполнить действия, соответствующие действиям ОС в аналогичной ситуации, а затем подтвердить их кнопкой **«Принять»** или предусмотренной в окне кнопкой подтверждения.

История шагов хранится в списке выполненных шагов. Некорректный шаг помечается красным цветом. При наведении указателя мыши на запись отображается информация о событии и действиях пользователя. Отмененные шаги помечаются серым цветом. В строке статуса отображаются число допущенных ошибок и, для диспетчера памяти, количество свободных параграфов ОП.

В лабораторной работе по диспетчеру памяти нужно выполнить **сорок шагов**. После выполнения всех сорока шагов первого задания не должно остаться неисправленных ошибок, после чего можно переходить ко второму заданию.

<a id="memory-lab"></a>
## 2. Задание 1 — управление памятью

В лабораторной работе реализовано распределение памяти динамическими разделами с использованием одного из трех алгоритмов выделения оперативной памяти.

<a id="memory-window"></a>
### 2.1. Окно диспетчера памяти

- В верхней части окна находится сообщение о наступившем событии; необходимо корректно на него отреагировать.
- В левой части находится список блоков памяти. Занятые блоки помечены голубым цветом, свободные — желтым. Для каждого блока указан начальный адрес, размер в параграфах и идентификатор процесса-владельца; `-1` означает, что владельца нет.
- В средней части расположен список свободных блоков памяти, который можно сортировать.
- В правой части находится список выполненных шагов; некорректные действия помечаются красным цветом.
- В нижней строке статуса показываются общее число ошибок и количество свободных параграфов оперативной памяти.

**Действия в интерфейсе:**

1. **Отказать в запросе** — нажать нижнюю кнопку отказа.
2. **Выделить память процессу** — щелкнуть правой кнопкой по свободному блоку в списке блоков памяти ОС, выбрать «Выделить приложению», затем в появившемся окне ввести идентификатор процесса и количество выделяемых параграфов.
3. **Освободить память** — щелкнуть правой кнопкой по занятому блоку и выбрать «Освободить». Память также освобождается при завершении процесса.
4. **Объединить свободные блоки** — щелкнуть правой кнопкой по свободному блоку и выбрать «Объединить со следующим». Это действие выполнять каждый раз, когда образуются соседние свободные блоки.
5. **Уплотнить память** — щелкнуть правой кнопкой по списку блоков памяти и выбрать «Уплотнить память».
6. **Подтвердить выполненные действия** — щелкнуть по верхней кнопке.

**Сортировка списка свободных блоков:** перетащить блок левой кнопкой мыши на нужное место. При щелчке на заголовке столбца клавиша `Shift` сохраняет сортировку по другим столбцам; `Ctrl` при щелчке на заголовке столбца отменяет сортировку по нему. Ширина столбца меняется перетаскиванием границы заголовка; порядок столбцов — перетаскиванием заголовка на нужное место.

<a id="memory-events"></a>
### 2.2. Общий алгоритм обработки событий памяти

**ДИСЦИПЛИНА / алгоритм:** обработка событий диспетчером памяти.

**ОПИСАНИЕ АЛГОРИТМА:** диспетчер памяти обрабатывает создание нового процесса, завершение процесса, выделение памяти существующему процессу и освобождение памяти, которой владеет процесс.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. При создании нового процесса проверить корректность идентификатора: он должен находиться в заданном диапазоне, и процесс с таким идентификатором не должен существовать.
2. При удалении процесса, выделении памяти существующему процессу и освобождении памяти проверить, что указанный процесс существует.
3. При освобождении блока проверить, владеет ли указанный процесс блоком памяти, который он освобождает.
4. Если свободного блока нужного размера нет, проверить суммарный размер свободных блоков. Если он больше или равен требуемому размеру, выполнить уплотнение (дефрагментацию) памяти.
5. Если суммарный размер свободной памяти недостаточен, выдать отказ на поступивший запрос.
6. Обратить внимание: в лабораторной методичке отдельно указано, что процесс нельзя поместить в свободный блок, который содержит столько же параграфов, сколько запрашивает данный процесс. Это специальное условие лабораторной модели; оно отличается от общей фразы основной методички о загрузке процесса в раздел равного или большего размера. При выполнении лабораторной работы следовать условию лабораторной методички.
7. При освобождении блока проверить, есть ли перед ним или после него свободные блоки. Если есть, все соседние свободные блоки объединить в один для уменьшения фрагментации.
8. Выполнить все сорок шагов. Перед переходом ко второму заданию неисправленных ошибок не должно оставаться.

<a id="first-fit"></a>
### 2.3. Алгоритм «Первый подходящий блок»

**ДИСЦИПЛИНА:** выбор первого подходящего блока (*first fit*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** список свободных блоков сортируется по адресу; выбирается первый блок, размер которого больше или равен требуемому размеру.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Посмотреть требуемое количество параграфов в сообщении о событии.
2. В списке свободных блоков расположить блоки в порядке адреса.
3. Последовательно просмотреть список от меньшего адреса к большему.
4. Выбрать первый блок, который подходит по размеру согласно правилу лабораторной модели.
5. При необходимости выделить память нужному процессу через контекстное меню «Выделить приложению» и ввести PID и количество параграфов.
6. Если подходящего блока нет, действовать по общему алгоритму: при достаточном суммарном объеме свободной памяти выполнить уплотнение; при недостаточном суммарном объеме — выдать отказ.
7. Подтвердить действия верхней кнопкой.

<a id="best-fit"></a>
### 2.4. Алгоритм «Самый подходящий блок»

**ДИСЦИПЛИНА:** выбор самого подходящего блока (*best fit*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** список свободных блоков сортируется по размеру от меньшего к большему; выбирается первый подходящий по размеру блок.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Определить требуемое количество параграфов.
2. Отсортировать свободные блоки по размеру в порядке возрастания.
3. Найти первый блок, подходящий по размеру.
4. Выделить память выбранному процессу через «Выделить приложению», введя PID и количество параграфов.
5. Если подходящего блока нет, проверить суммарный размер свободной памяти. При достаточном суммарном объеме выполнить уплотнение; если суммарного объема недостаточно — отказать в запросе.
6. Подтвердить действия верхней кнопкой.

<a id="worst-fit"></a>
### 2.5. Алгоритм «Самый неподходящий блок»

**ДИСЦИПЛИНА:** выбор самого неподходящего блока (*worst fit*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** самый неподходящий блок — блок с максимальным размером. Список свободных блоков необходимо отсортировать в порядке убывания размера и выбрать первый блок.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Определить требуемое количество параграфов.
2. Отсортировать свободные блоки по размеру в порядке убывания.
3. Выбрать первый блок в отсортированном списке — блок максимального размера.
4. Выделить память выбранному процессу через «Выделить приложению», введя PID и количество параграфов.
5. Если подходящего блока нет, действовать по общему алгоритму уплотнения или отказа, исходя из суммарного размера свободной памяти.
6. Подтвердить действия верхней кнопкой.

## 3. Задание 2 — планирование и диспетчеризация процессов

**Планирование процессов** — определение очередности получения ресурсов вычислительной системы для процессов при их активизации. **Диспетчеризация процессов** — определение очередности получения процессора для процессов, находящихся в состоянии готовности.

<a id="process-window"></a>
### 3.1. Окно диспетчера процессов

В верхней части окна отображается событие. В центральной части находится список процессов. Состояние отображается цветом строки, значком и буквой в столбце «Состояние»:

- `E` — процесс выполняется;
- `A` — процесс готов к выполнению;
- `W` — процесс обратился к устройствам ввода-вывода и ожидает завершения обмена.

В списке также находятся PID, PPID, текущий и базовый приоритеты (для Windows NT), время выполнения `t`, предполагаемое время выполнения `T` и разность `T-t`. Если значение `T-t` отрицательное, вместо числа отображается `-`.

В правой части расположены два окна очередей. В любом из них можно отобразить любую очередь с номером от 1 до 15. Чтобы добавить значение в конец очереди, нужно ввести его в нижнее окно ввода и нажать нижнюю кнопку с синей стрелкой. Чтобы извлечь значение из очереди, нужно нажать верхнюю кнопку с синей стрелкой; извлеченное значение помещается в окно ввода над кнопкой. В левом окне можно менять порядок элементов очереди перетаскиванием мышью.

**Действия пользователя в окне:**

- выдать отказ на запрос — нажать «Принять», не выполняя других действий;
- добавить процесс — щелкнуть правой кнопкой по списку процессов, выбрать «Добавить», ввести идентификатор, идентификатор родителя (если родителя нет — `-1`), базовый и текущий приоритеты, предполагаемое и текущее время выполнения и состояние, затем нажать «OK»;
- добавить PID в очередь;
- изменить порядок элементов очереди;
- прочитать значение из начала очереди;
- удалить процесс из списка процессов и очереди через контекстное меню «Удалить»;
- переключить процесс в состояние ожидания;
- переключить процесс в состояние готовности;
- выбрать процесс для выполнения через пункт «Переключиться».

Ответные действия необходимо завершать нажатием кнопки «Принять» в правом верхнем углу окна.

<a id="process-events"></a>
### 3.2. Проверки при обработке событий

Диспетчер задач обрабатывает создание нового процесса, создание дочернего процесса, завершение процесса, запрос на ввод-вывод, завершение ввода-вывода, передачу процессом управления ОС и истечение кванта времени для дисциплин с вытесняющей многозадачностью.

Перед выполнением действия проверить следующее:

1. Заданные значения должны находиться в соответствующих диапазонах.
2. При создании нового процесса и дочернего процесса процесс с таким PID не должен существовать.
3. Дочерний процесс может быть порожден только процессом, выполняющимся в данный момент.
4. Запрос на ввод-вывод и запрос на передачу управления ОС может выдать только выполняющийся процесс.
5. Завершение ввода-вывода может произойти только для процесса, находящегося в состоянии ожидания завершения операций ввода-вывода.
6. При завершении процесса удаляются и его дочерние процессы.
7. При отсутствии активных и готовых процессов никаких действий не выполнять.

В лабораторной модели реализовано 15 очередей, в которых хранятся активные (готовые к выполнению), но не выполняющиеся процессы. Процесс помещается в очередь при создании, при переходе из ожидания в активное состояние и при смене выполняемого процесса по истечении кванта. Извлечение из очереди выполняется при смене процесса, чтобы определить PID, которому ОС должна передать управление.

**Важно:** даже если в системе только один активный процесс и поступило сообщение о передаче управления другому процессу (то есть самому себе), операции помещения в очередь и извлечения из очереди нужно выполнить. При динамических приоритетах помещение в очередь также может требоваться для изменения приоритета.

Смена выполняемого процесса может произойти при передаче управления ОС, истечении кванта времени, создании нового процесса и завершении ввода-вывода.

<a id="lab-fcfs"></a>
### 3.3. Дисциплина FCFS

**ДИСЦИПЛИНА:** FCFS (*first come – first served*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** новые процессы добавляются в очередь 2, остальные — в очередь 1. Выбор PID процесса для передачи ему управления осуществляется из очереди 1; если она пуста — из очереди 2. Если есть только один активный процесс, очереди не используются. Если очередь 1 пуста и приходит событие передачи процессом управления ОС, диспетчер не выполняет никаких операций.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

**При завершении ввода-вывода ожидающего процесса:**

1. Переключить процесс в состояние готовности.
2. Добавить процесс в очередь 1.
3. Нажать «Принять».

**При передаче управления ОС активным процессом:**

1. Добавить выполняющийся процесс в очередь 1.
2. Извлечь PID из очереди 1; если она пуста — из очереди 2.
3. Переключиться на новый процесс, если PID извлечен.
4. Нажать «Принять».

При других событиях выполнять общие проверки диспетчера задач и правила помещения нового процесса в очередь, указанные выше.

<a id="lab-sjn"></a>
### 3.4. Дисциплина SJN

**ДИСЦИПЛИНА:** SJN (*shortest job next*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** работает только очередь 1. После помещения процесса в очередь необходимо переместить его на соответствующее место. Для SJN вперед помещаются процессы с меньшим заданным временем выполнения — поле `T`. Если время выполнения процесса превышает заданное, ему назначается штраф. При помещении в очередь такой процесс не перемещается, а остальные процессы, даже с большим временем, при помещении в очередь ставятся перед ним.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Проверить корректность события по общим правилам диспетчера задач.
2. При помещении готового процесса в очередь использовать только очередь 1.
3. Отсортировать очередь так, чтобы впереди находились процессы с меньшим значением `T`.
4. Если процесс превысил заданное время выполнения и получил штраф, при помещении в очередь не перемещать его; остальные процессы при помещении в очередь ставить перед ним, даже если у них большее время.
5. При создании нового процесса или завершении ввода-вывода процесса с меньшим временем выполнения **не выполнять немедленную передачу управления** только по этой причине.
6. Когда выполняющийся процесс передает управление ОС, выбрать процесс по очереди, сохраняя установленный порядок.
7. Подтвердить ответ кнопкой «Принять».

<a id="lab-srt"></a>
### 3.5. Дисциплина SRT

**ДИСЦИПЛИНА:** SRT (*shortest remaining time*).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** работает только очередь 1. После помещения процесса в очередь необходимо переместить его на соответствующее место. Для SRT вперед помещаются процессы с меньшим оставшимся временем — поле `T-t`. Если время выполнения процесса превышает заданное, ему назначается штраф; при помещении в очередь такой процесс не перемещается, а остальные процессы при помещении в очередь ставятся перед ним.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Проверить корректность события по общим правилам диспетчера задач.
2. Использовать только очередь 1.
3. После помещения процесса в очередь упорядочить ее по возрастанию оставшегося времени `T-t`: меньшее значение — ближе к началу очереди.
4. Если процесс превысил заданное время выполнения и получил штраф, не перемещать его при помещении в очередь; остальные процессы при помещении в очередь ставить перед ним, даже если у них большее оставшееся время.
5. При создании нового процесса или завершении ввода-вывода процесса с меньшим оставшимся временем **не выполнять немедленную передачу управления** только по этой причине.
6. При передаче управления ОС выбрать процесс в соответствии с очередью 1.
7. Подтвердить ответ кнопкой «Принять».

<a id="lab-rr"></a>
### 3.6. Дисциплина RR

**ДИСЦИПЛИНА:** RR (*round robin*, круговая дисциплина).

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** используется только очередь 1, которая заполняется в порядке пребывания. Отсутствуют какие-либо приоритеты.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. При создании процесса проверить корректность PID и остальные общие правила, после чего поместить процесс в очередь 1 в порядке поступления.
2. Если процесс переходит из ожидания ввода-вывода в готовность, вернуть его в активное состояние и поместить PID в очередь 1 в порядке пребывания.
3. При истечении кванта времени поместить выполнявшийся процесс в очередь 1.
4. При смене выполняемого процесса извлечь PID из начала очереди 1 и переключиться на этот процесс.
5. При передаче управления ОС выполнить помещение текущего процесса в очередь и выбор следующего по очереди согласно общему алгоритму диспетчера.
6. Не сортировать процессы по приоритетам: в этой дисциплине приоритеты отсутствуют.
7. Подтвердить действия кнопкой «Принять».

*Примечание по источнику:* описание RR в лабораторной методичке кратко задает одну очередь, порядок пребывания и отсутствие приоритетов; обработка помещения и извлечения из очереди берется из общего алгоритма работы диспетчера задач.

<a id="lab-unix"></a>
### 3.7. Дисциплина диспетчеризации ОС UNIX

**ДИСЦИПЛИНА:** упрощенная модель планирования процессов с динамическими приоритетами в ОС UNIX.

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** для режима задачи приоритет меняется в диапазоне 1–7, для режима ядра — 8 (системный диапазон). Процессы с приоритетами 9–15 имеют фиксированный приоритет. Процессу, ожидающему недоступного в данный момент ресурса, система определяет приоритет сна `8`. Когда процесс пробуждается, ядро устанавливает текущий приоритет равным приоритету сна. После завершения системного вызова перед возвращением в режим задачи ядро восстанавливает приоритет режима задачи, сохраненный перед системным вызовом.

При истечении кванта времени или передаче управления ОС процессорное время передается процессу с высшим приоритетом, стоящему первым в очереди. При создании процесса или завершении ввода-вывода процесса с более высоким приоритетом, чем у активного, происходит переключение на этот процесс.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. При создании процесса проверить допустимость PID и убедиться, что такого PID еще нет.
2. При помещении процессов в очереди учитывать приоритеты: режим задачи — 1–7; режим ядра — 8; фиксированные приоритеты — 9–15.
3. Если процесс ожидает недоступного ресурса, установить состояние ожидания; для ожидающего процесса используется приоритет сна `8`.
4. При завершении ввода-вывода переключить ожидающий процесс в состояние готовности и установить текущий приоритет равным приоритету сна.
5. Если выполнение системного вызова завершено и процесс возвращается в режим задачи, восстановить приоритет режима задачи, сохраненный перед системным вызовом.
6. При истечении кванта времени или передаче управления ОС просмотреть очередь и выбрать процесс с высшим приоритетом, стоящий первым.
7. При создании процесса или завершении ввода-вывода проверить, выше ли его приоритет, чем у активного процесса. Если выше — переключиться на него.
8. Подтвердить действия кнопкой «Принять».

<a id="lab-windows"></a>
### 3.8. Дисциплина диспетчеризации ОС Windows NT

**ДИСЦИПЛИНА:** упрощенная модель диспетчеризации процессов с динамическими приоритетами для Windows NT.

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** используются 15 очередей. Текущий приоритет процесса соответствует номеру очереди, в которой он находится. При помещении в очередь в результате передачи управления ОС или истечения кванта времени текущий приоритет уменьшается на единицу, то есть процесс помещается в очередь с меньшим номером. По завершении ввода-вывода ожидающему процессу назначается добавка приоритета — он помещается в более приоритетную очередь. Значение текущего приоритета не может опуститься ниже базового приоритета процесса или достигнуть 16.

Для выбора процесса, которому следует передать управление, просматривают очереди, начиная с самой приоритетной. Если очередь не пуста, из нее извлекается PID процесса, на который осуществляется переключение процессора. При создании процесса или завершении ввода-вывода процесса с более высоким приоритетом, чем у активного, происходит переключение на этот процесс.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. При создании процесса проверить допустимость PID и убедиться, что такого PID еще нет.
2. Определить текущий приоритет процесса и соответствующую очередь: номер очереди равен текущему приоритету.
3. При передаче управления ОС или истечении кванта времени уменьшить текущий приоритет на единицу и поместить процесс в очередь с меньшим номером, соблюдая ограничения модели: приоритет не ниже базового и не достигает 16.
4. При завершении ввода-вывода перевести ожидающий процесс в готовность и назначить добавку приоритета, поместив его в более приоритетную очередь; не опускать приоритет ниже базового и не допускать значения 16.
5. Для выбора следующего процесса просмотреть очереди, начиная с самой приоритетной.
6. Из первой непустой очереди извлечь PID и переключиться на соответствующий процесс.
7. При создании процесса или завершении ввода-вывода сравнить его приоритет с приоритетом активного процесса. Если он выше — переключиться на новый/готовый процесс.
8. Подтвердить действия кнопкой «Принять».

<a id="lab-os2"></a>
### 3.9. Дисциплина диспетчеризации OS/2

**ДИСЦИПЛИНА:** упрощенная модель диспетчеризации процессов с динамическими приоритетами для OS/2.

**ОПИСАНИЕ ДИСЦИПЛИНЫ:** классу критических задач принадлежит диапазон приоритетов 13–15, приоритетному классу — 9–12, стандартному классу — 5–8, остаточному классу — 1–4. Приоритет задачи увеличивается, когда она становится активной. По завершении операции ввода-вывода задача получает самый высокий уровень приоритета своего класса.

При создании процесса с приоритетом выше приоритета активного процесса происходит переключение на вновь созданный процесс. Если после завершения ввода-вывода приоритет процесса оказался выше приоритета активной задачи, происходит то же самое. Для выбора процесса очереди просматривают начиная с самой приоритетной; из первой непустой очереди извлекают PID и выполняют переключение.

**КОНКРЕТНЫЕ ШАГИ ДЛЯ ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ:**

1. Проверить корректность события и PID по общим правилам диспетчера задач.
2. Определить класс процесса по диапазону приоритетов:
   - критический — 13–15;
   - приоритетный — 9–12;
   - стандартный — 5–8;
   - остаточный — 1–4.
3. Когда задача становится активной, увеличить ее приоритет по правилу лабораторной модели.
4. При завершении ввода-вывода перевести процесс в состояние готовности и установить самый высокий уровень приоритета его класса.
5. При создании процесса сравнить его приоритет с приоритетом активного процесса; если новый процесс имеет более высокий приоритет, переключиться на него.
6. После завершения ввода-вывода также сравнить приоритет готового процесса с приоритетом активной задачи. Если он выше — переключиться на него.
7. Для обычного выбора следующего процесса просмотреть очереди от самой приоритетной к менее приоритетным, извлечь PID из первой непустой очереди и переключиться.
8. Подтвердить действия кнопкой «Принять».
