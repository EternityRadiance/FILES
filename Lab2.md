\# Файл 2. Алгоритмы действий по дисциплинам диспетчеризации процессов



\## Основные понятия



| Понятие | Значение |

|---|---|

| Процесс | Выполняющаяся программа, единица работы ОС |

| PID | Идентификатор процесса |

| PPID | Идентификатор родительского процесса; `-1`, если родителя нет |

| Состояние E | Процесс выполняется |

| Состояние A | Процесс готов к выполнению |

| Состояние W | Процесс ожидает завершения ввода/вывода |

| Очередь | Список PID процессов, готовых к выполнению, но не выполняющихся в данный момент |

| ВВ | Ввод/вывод |

| Ожидание ввода пользователя | Частный случай запроса на ВВ: процесс переходит в состояние W |

| `T` | Предполагаемое время выполнения процесса |

| `t` | Фактическое время выполнения процесса |

| `T - t` | Оставшееся время до предполагаемого завершения |

| Штраф | Ситуация, когда `t > T`; процесс не продвигается вперёд по очереди |

| Квант времени | Отрезок процессорного времени, после которого процесс снимается с выполнения |

| Текущий приоритет | Приоритет процесса, по которому он выбирается из очередей |

| Базовый приоритет | Нижняя граница текущего приоритета в Windows NT |

| Класс приоритета | Диапазон приоритетов в OS/2 |

| Активное повышение | Повышение приоритета процесса, когда он становится выполняющимся в OS/2 |

| Повышение после ВВ | Установка приоритета после завершения ввода/вывода в Windows NT и OS/2 |

\# 1. Дисциплина FCFS



\## Особенности



\- FCFS — невытесняющая дисциплина.

\- Новые процессы добавляются в очередь 2.

\- Остальные готовые процессы добавляются в очередь 1.

\- Выбор процесса для выполнения:

&#x20; 1. сначала из очереди 1;

&#x20; 2. если очередь 1 пуста — из очереди 2.

\- Если в системе только 1 активный процесс, очереди не используются.

\- Если очередь 1 пуста и приходит событие «передача управления ОС», диспетчер не выполняет никаких операций.

\- Квант времени не используется.



\## План действий



| Событие | Конкретные шаги |

|---|---|

| Появление нового процесса | 1. Проверить, что PID нового процесса корректен и ещё не существует. 2. Добавить процесс в список процессов в состоянии A. 3. Поместить PID нового процесса в очередь 2. 4. Если выполняющегося процесса нет: извлечь PID из очереди 1; если очередь 1 пуста — из очереди 2; перевести извлечённый процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять. |

| Создание дочернего процесса | 1. Проверить, что родитель находится в состоянии E. 2. Проверить, что PID дочернего процесса ещё не существует. 3. Добавить дочерний процесс в список в состоянии A. 4. Поместить PID дочернего процесса в очередь 2. 5. Переключение не выполнять, родитель продолжает выполняться. |

| Завершение процесса | 1. Проверить, что процесс существует. 2. Удалить процесс из списка процессов. 3. Удалить все дочерние процессы этого процесса. 4. Удалить удалённые PID из очереди 1 и очереди 2. 5. Если завершался процесс в состоянии E: извлечь PID из очереди 1; если очередь 1 пуста — из очереди 2; перевести извлечённый процесс в состояние E. 6. Если завершался процесс не в состоянии E: переключение не выполнять. |

| Запрос на ВВ / ожидание ввода пользователя | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в W. 3. Извлечь PID из очереди 1; если очередь 1 пуста — из очереди 2. 4. Перевести извлечённый процесс в состояние E. 5. Если очередей нет и извлекать нечего: процессор остаётся свободным. |

| Завершение ВВ | 1. Проверить, что процесс находится в состоянии W. 2. Перевести процесс из W в A. 3. Поместить PID процесса в очередь 1. 4. Если выполняющегося процесса нет: извлечь PID из очереди 1; если очередь 1 пуста — из очереди 2; перевести извлечённый процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять. |

| Передача управления ОС | 1. Проверить, что процесс находится в состоянии E. 2. Если очередь 1 пуста: не выполнять никаких операций. 3. Если очередь 1 не пуста: перевести текущий процесс из E в A. 4. Поместить PID текущего процесса в очередь 1. 5. Извлечь PID из очереди 1; если очередь 1 стала пуста — извлечь из очереди 2. 6. Перевести извлечённый процесс в состояние E. |

| Истечение кванта времени | Не применяется. FCFS — невытесняющая дисциплина без квантования. |

\# 2. Дисциплина SJN



\## Особенности



\- SJN — невытесняющая дисциплина.

\- Работает только очередь 1.

\- Процессы упорядочиваются по возрастанию `T`.

\- Меньшее `T` — выше место в очереди.

\- Если `t > T`, процесс получает штраф.

\- Штрафной процесс при помещении в очередь не продвигается вперёд.

\- Остальные процессы, даже с большим `T`, при помещении в очередь ставятся перед штрафным процессом.

\- При появлении нового процесса или завершении ВВ процесса с меньшим `T` переключение управления не выполняется.

\- Квант времени не используется.



\## План действий



| Событие | Конкретные шаги |

|---|---|

| Появление нового процесса | 1. Проверить, что PID нового процесса корректен и ещё не существует. 2. Добавить процесс в список процессов в состоянии A. 3. Вставить PID нового процесса в очередь 1 по правилу SJN: если `t > T`, оставить процесс позади непрощтрафных процессов; иначе вставить так, чтобы процессы с меньшим `T` шли раньше. 4. Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять. |

| Создание дочернего процесса | 1. Проверить, что родитель находится в состоянии E. 2. Проверить, что PID дочернего процесса ещё не существует. 3. Добавить дочерний процесс в список в состоянии A. 4. Вставить PID дочернего процесса в очередь 1 по правилу SJN. 5. Переключение не выполнять. |

| Завершение процесса | 1. Проверить, что процесс существует. 2. Удалить процесс из списка процессов. 3. Удалить все дочерние процессы этого процесса. 4. Удалить удалённые PID из очереди 1. 5. Если завершался процесс в состоянии E: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 6. Если завершался процесс не в состоянии E: переключение не выполнять. |

| Запрос на ВВ / ожидание ввода пользователя | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в W. 3. Извлечь PID из начала очереди 1. 4. Перевести извлечённый процесс в состояние E. 5. Если очередь 1 пуста: процессор остаётся свободным. |

| Завершение ВВ | 1. Проверить, что процесс находится в состоянии W. 2. Перевести процесс из W в A. 3. Вставить PID процесса в очередь 1 по правилу SJN, учитывая штраф при `t > T`. 4. Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять, даже если у пробудившегося процесса меньшее `T`. |

| Передача управления ОС | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в A. 3. Вставить PID процесса в очередь 1 по правилу SJN. 4. Извлечь PID из начала очереди 1. 5. Перевести извлечённый процесс в состояние E. |

| Истечение кванта времени | Не применяется. SJN — невытесняющая дисциплина без квантования. |

\# 3. Дисциплина SRT



\## Особенности



\- SRT — невытесняющая дисциплина в лабораторной модели.

\- Работает только очередь 1.

\- Процессы упорядочиваются по возрастанию `T - t`.

\- Меньшее оставшееся время `T - t` — выше место в очереди.

\- Если `t > T`, значение `T - t` отрицательное, процесс получает штраф.

\- Штрафной процесс при помещении в очередь не продвигается вперёд.

\- Остальные процессы, даже с большим оставшимся временем, при помещении в очередь ставятся перед штрафным процессом.

\- При появлении нового процесса или завершении ВВ процесса с меньшим `T - t` переключение управления не выполняется.

\- Квант времени не используется.



\## План действий



| Событие | Конкретные шаги |

|---|---|

| Появление нового процесса | 1. Проверить, что PID нового процесса корректен и ещё не существует. 2. Добавить процесс в список процессов в состоянии A. 3. Вычислить `T - t`. 4. Вставить PID нового процесса в очередь 1 по правилу SRT: если `T - t < 0`, оставить процесс позади непрощтрафных процессов; иначе вставить так, чтобы процессы с меньшим `T - t` шли раньше. 5. Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 6. Если выполняющийся процесс есть: переключение не выполнять. |

| Создание дочернего процесса | 1. Проверить, что родитель находится в состоянии E. 2. Проверить, что PID дочернего процесса ещё не существует. 3. Добавить дочерний процесс в список в состоянии A. 4. Вычислить `T - t` дочернего процесса. 5. Вставить PID дочернего процесса в очередь 1 по правилу SRT. 6. Переключение не выполнять. |

| Завершение процесса | 1. Проверить, что процесс существует. 2. Удалить процесс из списка процессов. 3. Удалить все дочерние процессы этого процесса. 4. Удалить удалённые PID из очереди 1. 5. Если завершался процесс в состоянии E: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 6. Если завершался процесс не в состоянии E: переключение не выполнять. |

| Запрос на ВВ / ожидание ввода пользователя | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в W. 3. Извлечь PID из начала очереди 1. 4. Перевести извлечённый процесс в состояние E. 5. Если очередь 1 пуста: процессор остаётся свободным. |

| Завершение ВВ | 1. Проверить, что процесс находится в состоянии W. 2. Перевести процесс из W в A. 3. Вычислить `T - t`. 4. Вставить PID процесса в очередь 1 по правилу SRT, учитывая штраф при отрицательном `T - t`. 5. Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 6. Если выполняющийся процесс есть: переключение не выполнять, даже если у пробудившегося процесса меньшее `T - t`. |

| Передача управления ОС | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в A. 3. Вычислить `T - t`. 4. Вставить PID процесса в очередь 1 по правилу SRT. 5. Извлечь PID из начала очереди 1. 6. Перевести извлечённый процесс в состояние E. |

| Истечение кванта времени | Не применяется. SRT в лабораторной модели — невытесняющая дисциплина без квантования. |

\# 4. Дисциплина RR



\## Особенности



\- RR — вытесняющая дисциплина.

\- Используется только очередь 1.

\- Очередь заполняется в порядке прибытия.

\- Приоритеты не используются.

\- Все готовые процессы равноправны.

\- Процесс выполняется до истечения кванта, запроса ВВ, передачи управления ОС или завершения.

\- После истечения кванта процесс помещается в конец очереди 1.

Поместить PID нового процесса в конец очереди 1. 4. Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять. |

| Создание дочернего процесса | 1. Проверить, что родитель находится в состоянии E. 2. Проверить, что PID дочернего процесса ещё не существует. 3. Добавить дочерний процесс в список в состоянии A. 4. Поместить PID дочернего процесса в конец очереди 1. 5. Переключение не выполнять. |

| Завершение процесса | 1. Проверить, что процесс существует. 2. Удалить процесс из списка процессов. 3. Удалить все дочерние процессы этого процесса. 4. Удалить удалённые PID из очереди 1. 5. | Запрос на ВВ / ожидание ввода пользователя | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в W. 3. Извлечь PID из начала очереди 1. 4. Перевести извлечённый процесс в состояние E. 5. Если очередь 1 пуста: процессор остаётся свободным. |

Если выполняющегося процесса нет: извлечь PID из начала очереди 1 и перевести процесс в состояние E. 5. Если выполняющийся процесс есть: переключение не выполнять. |

| Передача управления ОС | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в A. 3. Поместить PID процесса в конец очереди 1. 4. Извлечь PID из начала очереди 1. 5. Перевести извлечённый процесс в состояние E. 6. Даже если извлечён тот же процесс, операции помещения в очередь и извлечения выполнить нужно. |

| Истечение кванта времени | 1. Проверить, что процесс находится в состоянии E. 2. Перевести процесс из E в A. 3. Поместить PID процесса в конец очереди 1. 4. Извлечь PID из начала очереди 1. 5. Перевести извлечённый процесс в состояние E. |

\# 5. Планирование процессов в ОС UNIX



\## Особенности



\- UNIX — вытесняющая дисциплина с приоритетами.

\- Используются очереди приоритетов от 1 до 15.

\- Чем выше число, тем выше приоритет.

\- Диапазоны:

&#x20; - 1–7 — режим задачи;

&#x20; - 8 — системный диапазон, приоритет сна;

&#x20; - 9–15 — фиксированные приоритеты.

\- Выбор процесса:

&#x20; 1. просматривать очереди от 15 до 1;

&#x20; 2. взять первую непустую очередь;

&#x20; 3. извлечь процесс, стоящий первым в этой очереди.

\- При создании процесса или завершении ВВ процесса с приоритетом выше активного происходит переключение на этот процесс.

\- Процесс, ожидающий недоступный ресурс, получает приоритет сна 8.

\- При пробуждении после ВВ текущий приоритет процесса устанавливается равным 8.

\- После завершения системного вызова перед возвратом в режим задачи восстанавливается сохранённый приоритет режима задачи.

\- При истечении кванта или передаче управления ОС выбирается процесс с высшим приоритетом, стоящий первым в своей очереди.



\## План действий



| Событие | Конкретные шаги |

|---|---|

| Появление нового процесса | 1. Проверить, что PID нового процесса корректен и ещё не существует. 2. Добавить процесс в список процессов в состоянии A. 3. Поместить PID нового процесса в конец очереди, номер которой равен его текущему приоритету. 4. Если выполняющегося процесса нет: просмотреть очереди от 15 до 1, взять первую непустую, извлечь первый PID, перевести процесс в состояние E. 5. Если выполняющийся процесс есть и приоритет нового процесса выше приоритета выполняющегося: поместить выполняющийся процесс в конец очереди его текущего приоритета; перевести новый процесс в состояние E. 6. Если приоритет нового процесса не выше выполняющегося: переключение не выполнять. |

| Создание дочернего процесса | 1. Проверить, что родитель находится в состоянии E. 2. Проверить, что PID дочернего процесса ещё не существует. 3. Добавить дочерний процесс в список в состоянии A. 4. Поместить PID дочернего процесса в конец очереди его текущего приоритета. 5. Если приоритет дочернего процесса выше приоритета родителя: поместить родителя в конец очереди его текущего приоритета; перевести дочерний процесс в состояние E. 6. Если приоритет дочернего процесса не выше родительского: переключение не выполнять. |

\# 6. Планирование процессов в ОС Windows NT



\## Особенности



\- Windows NT — вытесняющая дисциплина с динамическими приоритетами.

\- Используются 15 очередей.

\- Текущий приоритет процесса соответствует номеру очереди.

\- Чем выше номер очереди, тем выше приоритет.

\- У процесса есть базовый приоритет.

\- Текущий приоритет не может опуститься ниже базового.

\- Текущий приоритет не может стать равным 16.

\- При передаче управления ОС или истечении кванта текущий приоритет уменьшается на 1.

\- После завершения ВВ процессу назначается добавка приоритета, то есть он помещается в более приоритетную очередь.

\- Выбор процесса:

&#x20; 1. просматривать очереди от 15 до 1;

&#x20; 2. взять первую непустую очередь;

&#x20; 3. извлечь первый PID.

\- При создании процесса или завершении ВВ процесса с приоритетом выше активного происходит переключение на этот процесс.

\# 7. Планирование процессов в OS/2



\## Особенности



\- OS/2 — вытесняющая дисциплина с динамическими приоритетами.

\- Используются очереди приоритетов от 1 до 15.

\- Чем выше число, тем выше приоритет.

\- Классы приоритетов:

&#x20; - критический: 13–15, максимальный приоритет класса 15;

&#x20; - приоритетный: 9–12, максимальный приоритет класса 12;

&#x20; - стандартный: 5–8, максимальный приоритет класса 8;

&#x20; - остаточный: 1–4, максимальный приоритет класса 4.

\- Приоритет задачи увеличивается, когда задача становится активной.

\- По завершении ВВ задача получает самый высокий приоритет своего класса.

\- При создании процесса с приоритетом выше активного происходит переключение на этот процесс.

\- При завершении ВВ, если приоритет ставшего готовым процесса выше приоритета активного, происходит переключение на этот процесс.

&#x20; 1. просматривать очереди от 15 до 1;

&#x20; 2. взять первую непустую очередь;

&#x20; 3. извлечь первый PID.
